C+E · Smart template / wizard

verdict: PARTIAL effort: S-M ⚠ schema impact (additive)

เปิด PDF ครั้งแรก → modal ถามประเภทผัง (4 ตัวเลือก) → seed layers + reportVars + tag default ให้. Workflow ใหม่: Open → ⊕ Pick type → Set Scale → Draw. dismissible.

กระทบ 5 constraints

constraintimpact
workflow เดิม⚠ เพิ่ม optional step
layer system⚠ pre-seed (additive ใน .bmaplan)
report variables⚠ pre-seed (มี reseed default อยู่แล้ว)
menu-flyout✓
code cap✓ ลง static/js/plan-wizard.js

ROI

  • ลด "ไม่รู้จะตั้ง layer อะไร" — ปัญหาใหญ่ของ CAD-newbie
  • ผูก domain ของ permit-plan (BMA) — proto ก็ยังไม่มี
  • ลายเซ็น UX ของ lite — แตกต่างจาก proto จริง ๆ

ที่ต้องระวัง

  • ต้องตัดสิน schema เพิ่ม: `.bmaplan.planType` ฟิลด์ใหม่ (additive, proto ignore ได้)
  • ถ้า user ข้าม wizard → default ของเดิมต้องยังใช้ได้
  • layer/reportVars defaults — กำหนดให้ดี ๆ ไม่งั้น user ต้องลบทิ้งทุกครั้ง

G · Progressive disclosure

verdict: PARTIAL effort: M ⚠ menu-flyout state-aware

เปิด lite → เห็นแต่ Open + Set Scale + Select/Pan.
Set scale เสร็จ → unlock Area / Distance / Snap / Reference / Count
วาด object แรก → unlock Annotate + ReportVars panel

กระทบ 5 constraints

constraintimpact
workflow เดิม⚠ บังคับลำดับ (hard gating)
layer system✓
report variables⚠ ซ่อน panel จนกว่ามี object
menu-flyout⚠ ต้องเขียน state-aware (greyed/enabled per condition)
code cap⚠ menu-flyout +rules engine ใหญ่ขึ้น

ROI

  • บังคับ user เดิน workflow ที่ถูก (= match memory ของ user "prefers hard gating over warnings")
  • ลด "ทำไมวัดออกเป็น pt ไม่ใช่ m" → เพราะ Area greyed จน set scale

ที่ต้องระวัง

  • กลายเป็น "annoying" ถ้า user advanced ต้องการข้าม — ต้อง escape hatch
  • menu-flyout เดิมเป็น static data — ต้อง refactor ให้ accept predicate per item
