## 2026-07-03 — UX-REVIEW-20260703 + BUG-20260703-lite-save-wipes-data (CRASH fix: Ctrl+S wiped all measurements + full UI/UX journey review + layer↔measurement invent checkpoint) — PASS (branch: main)

**What changed:** Three pieces filed/shipped back-to-back the same morning. **(1) CRASH fix — save wiped all data (commit `d40b20b`):** Ctrl+S wrote an empty `.bmaplan` and destroyed the in-memory session. Root cause: `pageMgr` seeded `PS_by_id` as `deepCopy` snapshots of `PS` taken at upload time (empty at that point); all drawing thereafter mutated live `PS` only, never the snapshots; `mi-save` → `_pmCommit` then projected those stale empty snapshots back over `PS` immediately before `buildPageStore()` serialized it — so save always wrote the empty upload-time state, discarding every measurement drawn since. 72 green tests missed this because every existing save test called `buildPageStore()` directly (the API path) and never drove the real `mi-save` click path. Fix: new `projectToGlobals(livePS)` resolves each page id's CONTENT from live `PS` by identity — baseline position via `_initialIds`, duplicates via a new `dupSrc` map that deep-copies the SOURCE page's live content, merged pages stay blank as intended; `_pmCommit` now passes `PS` through this resolver, and model snapshots are refreshed post-commit so they stop going stale. The same latent wipe existed on the Apply/merge path (`_pmuiApplyChanges` + merge, `lite/static/js/page-manager-ui.js`, 2 call sites) — commit order was backwards (flush-then-commit instead of commit-with-pre-flush-baseline-then-flush); reordered to commit first. NEW guard `lite/tests/test_save_clickpath.py` (`LITE_SAVE_CLICKPATH_OK`) drives the REAL `mi-save` click via `URL.createObjectURL` interception — the click-path-vs-API-path gap that let 72 green tests miss this bug in the first place. Proven RED pre-fix (exact journey repro: polys 0, calib null after save) → GREEN; 4 checks including "duplicate page content follows identity, not position." Regression 17/17 (metamorphic suite, page-manager suite, apply-mutations, all persist suites, arc/CFSS summary parities, `MEASURE_PARITY_OK`). Files: `lite/static/js/page-manager.js` (+38/−, `projectToGlobals`), `lite/static/js/page-manager-ui.js` (+8/−, Apply/merge commit-order fix, 2 sites), `lite/tests/test_save_clickpath.py` (NEW, 190 lines), `lite/ui-lite.html` (+4/−), plus `docs/status/PHASE_INDEX.md` + `lite/tests/bug-archive.jsonl` bookkeeping (commit `912c3e2`). **(2) UI/UX review complete (filed as `UX-20260703-review-findings`, commit `2249400`):** a full journey review on the real 45-page permit PDF (29 screenshots captured to `artifacts/ux-review-20260703/`) plus a static code inventory surfaced 9 FRICTION findings — F-1 dead ⇧D hotkey, F-2 `F`/Focus key collision, F-3 Page Manager undiscoverable (⇧F12-only, no menu/button path), F-4 scale-verified state invisible after the verify modal closes, F-5 the setup wizard silently blocks all mouse input with no visible modal cue, F-6 misleading "เปิด PDF ก่อน" message shown during a still-in-flight background upload, F-7 `modalOpen()` fails to recognize `#sum`/`#vs-modal`/the cheatsheet as open modals so typing in them fires tool hotkeys instead of being captured, F-8 raw/unfriendly error messages surfaced to the user, F-9 the Verify Scale flow uses a native `window.prompt()` instead of the app's own modal system — plus 6 COSMETIC findings (annotate mode has no hotkeys documented, Thai/English label inconsistency in a few places, the on-screen cheatsheet is stale vs. actual bindings, empty-state UI feels cluttered, a transient "scanned PDF" notice disappears too fast to read, no visible fallback-render badge when PDF.js degrades to raster) and 3 GOODs explicitly pinned so future refactors don't regress them (the setup wizard flow, the local-first "green dot" save status, and live in-progress measurement feedback on the canvas). This is a findings-filing sprint — no application code changed by the review itself (the CRASH bug it surfaced was already fixed same-morning by piece 1). **(3) Layer↔measurement invent at checkpoint (`INV-20260703-layer-linkage`, commit `2249400`):** an investigation mapped the current layer/measurement data model and enumerated 8 concrete problems (3 rated HIGH: no UI exists to move an object between layers once drawn; the Summary-widget aggregation engine and the Review-panel aggregation engine can disagree on net area because they are two independently-maintained rollup implementations; an orphaned `catId` — e.g. after a category is deleted — silently drops the object from every total with no warning, and in one path crashes). The `bma-inventor` diverge/score phase produced 5 candidate approaches; Approach B "one aggregation engine" won 25/30 — a single `object-agg.js` tuple-stream generator that every current consumer (summary, review, export, per-floor net) is rewritten as a pure reduction over, making per-floor net calculation native instead of bolted-on, and is fully additive (no schema break). Fallback approach D (a simpler `floorKey` field directly on objects) was also scored and recorded in case B proves too large. A staged rollout plan B0→B5 was written. The pipeline received GO from the human checkpoint; **B0 (the tuple generator + a new `I11` invariant oracle) and a first batch of UX quick-wins (F-7 modal-detection fix, F-1/F-2/F-3 hotkey/discoverability fixes, plus a cheatsheet accuracy pass) are being built right now by two `lite-builder` subagents running in parallel** — recorded here as in-progress, not yet shipped; nothing from B0 or the UX quick-wins batch landed in this docs-write's commit range.

**Why:** The save-wipe bug is the most severe class of defect this project tracks — total, silent, undetected data loss on the single most-used action in the app (Ctrl+S) — and it slipped through 72 previously-green tests because every one of them called the serialization function directly rather than driving the actual UI click handler a real user triggers. That gap is now closed with a guard that fires the real event, and it is the concrete incident this block wants captured as an `INVARIANTS.md`-style lesson: click-path coverage is not implied by API-path coverage, and any future save/persistence-adjacent guard must drive the real handler, not just the underlying function. The UX review exists to surface exactly this kind of pre-catastrophic friction before a user hits it in the field — the CRASH it found (piece 1) is the review methodology validating itself in the same session it was run. The layer-linkage investigation is upstream, deliberate R&D discipline (Pack H): rather than patch each of the 8 problems ad hoc as separate bug reports, the investigation first asked whether they share a root cause (they do — two independently-maintained rollup engines) and scored a structural fix before committing engineering time, exactly the RESEARCH-before-BUILD discipline this project's process docs require. The checkpoint halted for human GO rather than being auto-promoted, per Pack H's non-negotiable human-risk-taking gate for invention work.

## 2026-07-03 — GO-20260703-invariants-streaming-worker-recycle (V2-U1 invariant registry + Range-streaming spike NOGO→RESHAPE + worker-recycle build) — PASS (branch: main)

**What changed:** Continuation of the same-day "GO" loop block, run right after `BLOCK-20260703-clear-queue` closed, 5 pieces of work: **(1) V2-U1 invariant registry (commit `6d6e39b`):** NEW `lite/tests/INVARIANTS.md` — a canonical registry of 10 invariants (I1–I10), each mapped to its guard test + tier, plus the two mandatory SCOPE questions ("which invariants does this feature touch" / "does it create a new object kind") that is the prevention mechanism `docs/process/DEVELOPMENT_V2_BLUEPRINT.md` U1 called for, born directly from the arc-summary/CFSS-summary postmortem where a new object kind silently bypassed 6 rollup consumers. The new-kind rule requires fixtures added to I2/I4/I5 in the same sprint a new kind is introduced, no exceptions. Same commit also reconciles 16 stale `PHASE_INDEX.md` rows (`lpm-1..9`, `cfss-guard`, `EVOLT-1..5`, `INV-2026-05-25-CFSS`) that claimed `queued` but were long since shipped — each now carries its real `fixed_commit` pulled from `bug-archive.jsonl`/the test suite, so the roadmap agrees with git history again. The queued `ptToScreen`/`screenToPt` parity-fixture card is closed with a rationale instead of code: the behavioral lock already exists as invariant I7 (`LITE_PAGEROT_REG_OK` asserts the 4-angle closed-form mapping + exact inverse at 1e-9, and runtime has routed through the parity-tested `pdfToC`/`cToPdf` kernel since `9f4b298`) — adding the two functions to the literal `test_measure_parity.py` fixture set was judged redundant work, not a real coverage gap. **(2) Range-streaming SPIKE (commits `9466fe4` + `f8c2981`), GO received via `/loop`:** the 5-step spike from `docs/invent/lite-range-streaming.md` was executed for real in `lite/sandbox/invent-range-streaming/` against RAMA4 (19 MB) and the real CHH binder (95 MB). Results: (S1) both customer PDFs are NON-linearized yet stream fine — only 20% of bytes were fetched, so the standing linearization concern turned out to be moot; (S2) Starlette's `/raw` route already serves `206 Partial Content` + `Content-Range` with zero backend changes needed; (S3) streaming cut CHH's RSS by only 10% (1675→1503 MB) against a ≥50% GO criterion — **FAILS**; PDF.js worker-heap bug #10730 was CONFIRMED on the pinned 4.0.379 build (`doc.destroy()` frees the main document heap 409→98 MB but the separate pdf.js WORKER heap survives untouched — this worker heap, not the document heap, is the real ~1.5 GB ceiling); (S4) `PDFDataRangeTransport` over `Blob.slice` works mechanically (no full local copy needed) but delivers no memory win given (S3). **VERDICT: NOGO on streaming-as-a-memory-fix**, RESHAPE to worker-recycle — the spike's whole point was to prevent a doomed build sprint from being attempted, and it did. **(3) worker-recycle BUILT (commit `d52ddbb`), the RESHAPE, GO via `/loop`:** `lite/static/js/page-renderer.js` gains explicit `PDFWorker` ownership (`_docWorker`, passed into `getDocument` from both the `openLocal` and `/raw` paths — previously pdf.js silently created an implicit worker per document that `doc.destroy()` could never fully reclaim) plus a cheap `_docSource` re-open handle (a retained local `File`/`Blob` reinit with zero network cost, or the `caseId` for a one-shot `/raw` refetch) plus `recycleDocWorker()` — guarded against re-entrant recycling, skipped outright if a render is in-flight or no source is retained, and preserving `pageDims`/`pageRot`/`_scanned` metadata across the teardown so the UI doesn't need to re-derive anything. The next `loadPage()` call after a recycle transparently triggers a lazy `_reinitDoc()` — no visible state change to the user beyond a brief re-render. Recycle triggers: tab hidden ≥60 s, app idle ≥5 min AND `pageCount>20` (small documents aren't worth recycling), and a manual `PageRenderer.recycleNow` hook for tests. `_resetCache()` now also destroys the explicit worker on new-upload, closing a latent leak where the old implicit-worker pattern would otherwise accumulate one abandoned worker per upload in a long session. `page-renderer.js` grows to 790/1000 lines; `lite/ui-lite.html` gains exactly one call-site line (1170 total). Built by the `lite-builder` subagent, independently verified by the main agent. NEW guard `lite/tests/test_worker_recycle.py` (`LITE_WORKER_RECYCLE_OK`, 7 checks: teardown state, transparent reinit repaint, zero-refetch when a local blob is retained, metadata survival, in-flight-render SKIP, and a heap-not-worse assertion measured at −0.8%). Honest scope note: the full "CHH RSS −50%" acceptance bar was measured in the earlier spike's pattern (S3), not re-measured against this specific production implementation — a production re-probe on the real CHH binder is recorded as the queued follow-up measurement, not assumed. Regression 6/6 files + `run_all_tests.py --tier t0` green. **(4) Streaming-as-bandwidth card DEFERRED-until-remote-deployment:** the optional second card proposed by the spike (Range-streaming purely as a bandwidth optimization, independent of the memory question) was evaluated and explicitly deferred rather than built, with a recorded rationale (เสา 1 — "build only what today's product needs"): all `/raw` byte transfer happens over localhost on the current desktop-only product (a real 91 MB `/raw` fetch measured at 498 ms), so the spike's 80% byte-count reduction has no user-facing benefit until a remote/networked deployment target actually exists. **Suite validation:** the lite test suite now stands at 72 files; `MEASURE_PARITY_OK` stayed green throughout every piece of this block — zero vendored-math touch.

**Why:** This block is the direct continuation of the invention discipline `BLOCK-20260703-clear-queue` Ship 3 deliberately halted at — Range-streaming research had reached a human checkpoint, and the "GO" loop resumed work only once that checkpoint was cleared. Running the spike for real (rather than trusting the desk-research verdict) is what caught that the ~1.5 GB memory ceiling is a pdf.js worker-heap defect (#10730), not a document-buffering problem that Range-streaming could ever have fixed — building the streaming feature first would have shipped real engineering effort against the wrong root cause. Pack H's RESHAPE path exists precisely for this outcome: redirect the same acceptance bar (large-PDF memory reduction) toward the mechanism the spike's own evidence pointed at (worker teardown), rather than either abandoning the goal or forcing the original approach through anyway. The V2-U1 invariant registry and the PHASE_INDEX reconciliation are process debt paid down opportunistically in the same session — the registry converts the arc/CFSS postmortem lesson into a mandatory SCOPE-time question instead of relying on memory of a past incident, and 16 stale roadmap rows were a small, mechanical fix once noticed. The streaming-as-bandwidth deferral is an explicit anti-scope-creep decision: it would have been easy to ship "80% fewer bytes" as a feel-good win, but the desktop-only product has no user who benefits from it today.
