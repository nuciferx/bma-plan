## Active Feature State (2026-07-02 — BUG-20260702-lite-pagerot-registration: ptToScreen/screenToPt now rotation-aware, export prerotates raster)

Bugfix, not a new feature — but it changes on-screen geometry registration and export output for any project that uses manual page rotation, so it's recorded here.

Intrinsic PDF `/Rotate` metadata was always handled correctly; only the manual rotate-page menu path was broken.

Geometry drawn WHILE a page was rotated got stored bound to the un-rotated frame — the reported area/length value stayed correct, but the on-screen location was wrong (attached to the wrong feature). `/export-pdf-overlay` did not apply `pageRot` at all, so exported annotated PDFs never matched what the user saw on screen whenever `pgRot≠0`.
