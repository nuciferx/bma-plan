2. เส้นทางข้อมูล 6 เส้นหลัก (ใครไหลไปหาใคร)

① เปิดไฟล์ผู้ใช้เลือก PDF→ FileReader อ่านเข้า memory→ PDF.js render บน canvaspage-renderer.js→ ส่งขึ้น server คู่ขนานได้ caseId ไว้ใช้ thumb/export→ wizard ติดป้ายหน้าเด้งwiz-auto → overview-setup
ถ้า upload ล้ม: ยังวัดได้ แต่ thumbnail/export ใช้ไม่ได้ (caseId ว่าง) — ที่มาของ "Page Manager เปิดไม่ได้" กรณีหนึ่ง
② ตั้ง scaleกด S คลิก 2 จุด→ คำนวณ pts_per_m→ เก็บใน PS[หน้า].scaleต่อหน้า ไม่ใช่ทั้งไฟล์→ ทุกตัวเลข m² คิดสดจากนี่ไม่มีการ cache ค่า — กฎเหล็ก
หน้าไม่มี scale → พื้นที่ = null แสดง "—" (ห้ามเป็น 0) = กติกา SCALE-GATE / I8
③ วาด/วัดคลิกบน canvas→ snap ปรับจุดsnap-engine (+centerline ถ้าเปิด)→ cToPdf แปลงเป็นพิกัด PDFmeasure-engine — ห้ามแก้→ เก็บ object ลง PS[หน้า].objectscatId + semanticTag ติดไปด้วย→ polyAreaM2 คิดพื้นที่โชว์ป้าย
④ หน้า+ชั้น+เลเยอร์ป้ายหน้าคือต้นน้ำ→ pageTags / pageFloorNumแก้ที่ wizard หรือเมนู→ สร้างโฟลเดอร์ชั้น PF_* อัตโนมัติpage-folder-layers (derive ใหม่ได้ตลอด)→ panel ขวาแสดงเฉพาะของหน้านี้layer-scope กรองตอน render
จุดที่เคยทำ "เลเยอร์มั่ว": ป้ายหน้าถูกล้างตอน Save (แก้แล้ว 878effd) → โฟลเดอร์ derive ใหม่จากข้อมูลเก่า → เลเยอร์ดูย้ายที่เอง
⑤ รวมยอดทุกที่ต้องได้เลขเดียวกัน→ objectTuples() ไล่ทุก objectobject-agg — ท่อกลางท่อเดียว→ byCategory / byRole / byFloor→ Σ สรุป · รายงาน · XLSX · ตัวแปร FAR/OSRผู้บริโภคทุกตัวดูดจากท่อนี้
กฎ: การคำนวณห้ามอ่านชื่อเลเยอร์ — ใช้ role/semanticTag เท่านั้น (invariant I2)
⑥ Save / Export→ Save = browser เขียน .bmaplan เองadditive-only ห้าม rename/ลบ field· Export XLSX/PDF = ส่ง payload ให้ server อบserver มี _rp() แปลงพิกัดกระจกกับ browser — ต้องตรงกัน (I5)

  • measure-engine.js — sha256 ล็อกไว้ แก้ 1 ตัวอักษรด่านเทสต์แดงทันที
